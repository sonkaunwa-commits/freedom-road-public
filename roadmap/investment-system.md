# Freedom Road 投资系统 Roadmap

> 本文件是 Freedom Road 总体 Roadmap 下的投资系统子路线图。只记录可公开的架构、优先级和工程边界；私人持仓、账户、密钥、执行价和 Private Ledger 不进入公开仓库。

## 2026-08-25：产品与数据边界正式确认

### 1. 两个独立产品

#### Freedom Road 投资系统
定位：用户自己的跨资产研究、资产配置、持仓管理、风险控制、复盘和策略验证系统。

正式模块包括：
- 市场数据中心 / Data Health；
- A股、港股、美股研究；
- 基金与 ETF 研究；
- 黄金/商品研究；
- 投资总账户与组合管理；
- 风险预算与仓位管理；
- 日报、周报、盘中快检；
- 策略回测与研究记录。

#### 基金小帮手
定位：独立的家用基金辅助应用，不属于用户个人投资账户，也不进入用户私人持仓模型。

它可以复用 Freedom Road 的：
- 公共基金数据；
- 基金基础研究算法；
- 通用评分/趋势/风险组件；
- 公共知识库；
- UI/发布基础设施。

但不得共享：
- 用户私人持仓；
- 用户投资总账户；
- 私人资金规模、成本、盈亏；
- 私有策略状态；
- 私人执行计划。

**原则：共享 infrastructure，不共享 personal state。**

## 2. 投资系统正式基金模块

基金模块是 Freedom Road 投资系统的一等模块，不是基金小帮手的放大版。

### 2.1 基金数据层（P1）
- 正式净值、盘中估算、申赎状态、基金经理、规模、持仓、行业、基准、费用等结构化数据；
- 盘中估算与正式净值严格分层；
- 保存日线与盘中历史；
- 记录 provider、timestamp、freshness、quality state；
- 建立估值误差数据库，识别不同主动基金盘中估值可信度。

### 2.2 全市场基金筛选（P1）
- 股票型、混合型、指数型、QDII 等；
- 排除不适合目标策略的货币、纯债、短债、同业存单、FOF 等；
- 综合中期收益、长期收益、最大回撤、波动、基金经理、规模、风格稳定、行业集中度和当前位置；
- 候选池保持少量、稳定、可解释；
- 换入/换出保留历史原因和评分轨迹。

### 2.3 交易辅助（P1）
输出不是单一“买/卖”，而是：
- 当前状态；
- 为什么；
- 第一笔/第二笔条件；
- 停止补仓条件；
- 持有条件；
- 利润保护；
- 退出/重新评估条件。

正式中长期判断以正式净值为主，盘中估算只做位置与执行时机辅助。

### 2.4 投资总账户联动（P1/P2）
基金进入用户自己的投资总账户后，需要与股票、黄金、现金、港股、美股统一分析：
- 资产类别占比；
- 地域暴露；
- 行业/主题重复；
- 相关性；
- 风险预算；
- 现金比例；
- 新增资金机会成本。

例如持有 AI 个股同时持有高集中 AI 基金时，应识别为同一风险因子的重复暴露，而不是机械视为分散。

### 2.5 组合日报（P1）
针对用户自己的基金仓位/基金子组合输出：
- 当日变化；
- 组合贡献/拖累；
- 需要处理；
- 持有/等待；
- 行业与主题集中；
- 资金分布；
- 数据完整度；
- 组合风险；
- 下一步动作。

### 2.6 策略回测（P2）
验证：
- 全市场筛选；
- 分批建仓；
- 趋势持有；
- 利润保护；
- 退出条件；
- 资金占用效率。

对比对象至少包括：
- 基金自身基准；
- 主要宽基指数；
- 单纯买入持有；
- 用户股票策略（仅在私人研究层）。

评价指标：收益、最大回撤、波动、胜率、交易次数、资金利用率、回撤恢复时间。

## 3. Fund Data Engine：共用基础设施

Fund Data Engine 是共享服务，不是共享账户。

```text
Fund Data Engine
├─ Public fund data / research outputs
│  ├─ 基金小帮手
│  └─ Freedom Road 公共研究组件
└─ Private fund data / account outputs
   └─ Freedom Road 投资总账户与私人研究
```

### 第一阶段（P1）
- 腾讯云交易日 09:30–15:00 运行；
- 默认每10分钟采样；
- 明确午间休市语义；
- 每条记录至少含 `trade_date`, `sample_time`, `fund_code`, `estimate_nav`, `estimate_pct`, `source`, `freshness`, `official_nav_date`；
- Parquet 保存历史，当日 JSON 供前端读取；
- public/private 输出路径严格分离。

### 数据质量门禁
- 旧交易日数据不得标成今天；
- stale 数据不得触发精确动作；
- 页面必须显示数据日期、更新时间和估算/正式状态；
- 服务器完整曲线与浏览器本地采样必须明确区分；
- 采集失败显式降级。

## 4. 与 Market Data Reliability 的关系

基金模块不单独再造一套数据健康体系，统一接入 Freedom Road `data_health`：
- provider；
- 更新时间；
- 最新交易日；
- freshness；
- coverage；
- degraded state；
- blocker。

报告层只有在数据健康门槛满足时，才允许产生精确操作级建议。

## 5. 优先级与实施顺序

### P0
1. 保持 public/private publication boundary；
2. 时间敏感金融页面强制显示日期、freshness、无数据/休市状态；
3. 继续修复市场数据可靠性和分钟级行情。

### P1
1. Fund Data Engine 第一版；
2. 基金盘中估值历史与误差数据库；
3. Freedom Road 基金筛选模块；
4. 个人基金组合日报；
5. 投资总账户跨资产暴露分析。

### P2
1. 基金策略回测；
2. 基金 vs ETF vs 个股机会成本比较；
3. 多模型研究与低成本模型路由；
4. 更深的组合相关性和风险因子分析。

## 6. 独立产品原则

后续开发时必须持续满足：
- 基金小帮手的功能需求不能自动变成 Freedom Road 个人投资需求；
- Freedom Road 私人账户功能不能自动暴露给基金小帮手；
- 可以复用公共数据和代码组件，但产品需求、用户数据、报告和发布节奏分别管理；
- 两个产品均受统一 Release Quality Gate 约束。
